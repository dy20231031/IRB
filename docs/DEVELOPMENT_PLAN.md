## 4. 다음 기능 구현 순서

1. **기관 담당자 확인 기록:** 미확인 규칙에 검토 상태와 근거를 연결한다. 문의를 자동 전송하지 않는다.
2. **서류 업로드와 항목 매핑:** 파일명 추정 결과를 사용자가 확인하게 한다. 업로드만으로 완성이라고 표시하지 않는다.
3. **문서 내용 검사:** 문서 파서, 필수 항목, 연구 제목과 대상자 수의 문서 간 불일치 검사. PDF와 DOCX부터 시작하고 HWP는 별도 지원 계획을 둔다.
4. **동의서와 연구계획서 초안 보조:** 기관 서식에 확인된 사실만 채우고 수정 위치를 표시한다. 초안과 제출본을 구분한다.
5. **공지 변경 감지:** 허용된 공개 페이지를 주기적으로 확인해 변경 후보만 알린다. 새 문구를 검수 없이 운영 규칙에 자동 반영하지 않는다.
6. **지원 기관과 절차 확대:** 새 기관마다 별도 근거, 범위와 평가 세트를 마련한다. 변경심의와 종료보고는 신규심의 규칙에 섞지 않는다.

## 역할 분담 예시

| 작업 영역 | 주 책임 | 다른 영역에 전달할 것 |
|---|---|---|
| 기관 데이터 | 자료 조사와 연구 행정 담당 | source ID, 적용 조건, 미해결 질문 |
| 판단과 AI | 백엔드 / Agent 개발 | 함수 인터페이스, 3단계 결과, 실패 처리 |
| 화면과 시연 | 프런트엔드 / 제품 담당 | 사용자 오류, 질문 소요 시간, 예시 시나리오 |
| 독립 검증 | 규칙 작성에 참여하지 않은 검토자 | 정답과 근거, 불일치 사례 |

독립 검토자는 개발자와 다른 관점으로 판정을 검증하는 역할이다. 인원이 적더라도 자기 회귀 테스트를 전문가 검증으로 표현하지 않는다.

## 변경할 파일 안내

- 기관 추가: `data/institutions.json`, `sources.json`, `rules.json`
- 질문 추가: `data/questions.json`, 관련 규칙의 `review_fields`, 회귀 사례
- AI 제공자 교체: `src/agent/llm.py`. `validate_proposals`와 사용자 확인 절차 유지
- API 서버 분리: `src/agent/api.py`의 함수를 감싸되 세션별 접근 제어와 저장 정책 먼저 설계
- 결과 디자인 변경: `app.py`, `src/agent/report.py`

## 완료의 정의

코드 변경 시 관련 위험을 재현하는 테스트를 통과하고, 데이터 변경 시 출처와 버전을 남긴다. 미해결 조건은 감추지 않는다. 사용자가 결과를 보고 “무엇을 준비하고, 무엇을 확인해야 하는가”를 구분할 수 있어야 한다.
