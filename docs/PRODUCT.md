# 제품 기획: 질문형 IRB 제출 준비 Agent

## 목적

연구자가 자신의 연구 조건을 빠뜨리지 않고 정리하고, 제출할 기관의 서류 및 전자 신청 과제와 연결하도록 돕는다. 결과물은 근거가 추적되는 준비 목록과 기관에 확인할 사항이다.

“모든 서류가 완벽하다” 또는 “승인된다”는 판정을 제공하지 않는다. 연구자가 답을 모를 때는 그 불확실성을 결과에 남긴다.

## 첫 두 기관을 선택한 이유

| 기관 | 구현 관점의 이유 | 적용 경계 |
|---|---|---|
| 가톨릭대학교 성심교정 | 공개 공지에서 참가자 정보별 동의서 조건과 연구자별 서류 조건을 확인할 수 있음 | 다른 교정과 병원의 IRB 규칙으로 확대하지 않음 |
| 서울교육대학교 | 공개 안내가 eIRB 입력 대체 항목과 첨부 항목을 구분함 | 서울대학교와 구분. 로그인 내부 화면은 아직 검증하지 않음 |

두 기관이 전체 IRB를 대표한다고 가정하지 않는다. 기관마다 같은 명칭의 서류도 조건과 제출 방식이 다를 수 있다는 점을 검증할 첫 범위로 삼는다.

## 사용자와 입력

주 사용자: 신규심의를 준비하는 대학원생과 연구 행정 담당자.

| 입력 | 목적 | 기본값 |
|---|---|---|
| 기관 | 규칙 집합 선택 | 지원 기관 중 선택 |
| 신규심의, 연구 방법, 성인 여부, 동의 경로 | 지원 범위 확인 | 아직 모름 |
| 대학원생과 전임교원 조건 | 연구자별 서류 확인 | 아직 모름 |
| 수집 정보와 처리 과정 | 참가자 동의 서식 조건 확인 | 미입력은 모름 |
| 연구 설명 | 선택적으로 사실 추출 제안 | 자동 반영하지 않음 |
| 준비 상태 | 사용자의 진행 표시 | 미확인 |

실제 참가자의 이름이나 연락처를 입력받을 필요가 없다. “이름을 수집하는가”처럼 연구 설계의 속성만 수집한다.

## 구체적 사용 예

1. 가톨릭대 소속 대학원생이 성인 설문 신규심의를 선택한다.
2. 설명에 “전화번호를 받지 않는다”고 쓰고 AI 해석을 선택한다.
3. AI가 제안한 `collect_phone=no`를 사용자가 확인한다. 이 값만으로 개인정보 동의서를 제외하지 않는다.
4. 추가 질문에서 “이름을 받는다” 또는 “기프티콘 발송용 연락처를 받는다”고 답한다.
5. 참가자 개인정보 동의서가 준비 대상으로 표시되고 어떤 답변을 근거로 했는지 보여준다.
6. 수집 범위에 모르는 사항이 있으면 이를 기관 확인 목록에 남긴다.
7. 사용자가 준비 상태를 표시하고 보고서를 내려받는다.

## 출력 정의

| 출력 | 의미 |
|---|---|
| 준비 필요 | 현재 범위와 확인한 사실에 기관 규칙을 적용한 준비 대상 |
| 현재 조건에서 비해당 | 명시적인 제외 조건을 만족한 특정 항목. 연구 전체의 심의 면제가 아님 |
| 확인 필요 | 사실 부족, 범위 밖, 공개 기준 불명확, 출처 재확인 필요 |
| 처리 방법 | 파일 준비 / eIRB 입력 / 기관 확인 과제 |
| 판단 이유 | 적용한 조건과 확인하지 못한 부분 |
| 출처 | 공식 URL, 확인일, 위치, 버전 메모 |
| 준비 상태 | 미확인 / 준비 중 / 준비함. 전부 사용자 표시이며 검증 결과가 아님 |

요구 여부와 준비 상태는 서로 독립적이다. 사용자가 파일을 주지 않았다는 이유로 “미제출”이라고 단정하지 않는다.

## 질문 종료 조건

- 더 이상 묻지 않은 관련 사실이 없으면 결과 화면으로 이동한다.
- 추가 질문은 최대 2회이며 회당 최대 3개 묶음이다. 묶음 안에는 세부 선택 항목이 있다.
- 사용자가 모른다고 답한 항목은 같은 평가에서 다시 묻지 않는다.
- 사용자가 중단하면 저장된 답변으로 부분 결과를 낸다.
- 지원 범위가 확인되지 않으면 추가 질문을 진행하지 않고 참고 목록과 범위 이슈를 보여준다.

## MVP 이후 확장

문서 업로드와 내용 확인, 기관 담당자 검수 규칙, 일정 수집, 면제와 변경심의 경로, 신청서 자동 작성은 별도 단계로 개발한다. 성인 연구라도 특수한 보호 조치가 필요할 수 있으며, 이 MVP가 모든 연구 대상 집단의 추가 요구를 포괄한다고 가정하지 않는다.
